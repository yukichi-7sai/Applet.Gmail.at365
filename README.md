# Applet.Gmail.at365

AppDockから、複数アカウントのGmail Web画面を開くAppletです。Googleの画面で利用者自身がログインし、アカウントごとにログイン状態を保存します。受信トレイの画面更新から新着を検知し、送信元・件名・検知時刻を新着一覧に表示します。アカウント一覧・AppDockのパネル・トレイの印とデスクトップ通知でも知らせます。

## 動作環境と導入

Windows x64、**AppDock 0.26.14以降**、Googleに接続できるインターネット環境が必要です。WebContentsViewはAppDock内蔵のElectronを使うため、別のブラウザーRuntimeやNode.jsのインストールは不要です。Gmail 0.9.1で追加したショートカット初期値の自動設定にはAppDock 0.25.2以降が必要です。

AppDockを完全終了し、配布された`Applet.Gmail.at365`フォルダー全体をEXE隣の`extensions`へ置きます。`extension.json`、`index.js`、`monitor.js`、`web/`が必要です。更新時もフォルダー全体を置き換え、`data`と`settings.json`は保持してください。起動後、Applet一覧で「Gmail」を有効にします。

## 表示方法

AppDockの「設定 → Gmail」で「Gmailの表示方法」を「AppDock本体のページ」または「別ウィンドウ」から選び、保存できます。表示先を変更してもログイン状態・選択アカウント・画面内の入力を保ちます。ホームや設定へ移動しても背景監視は続きます。別ウィンドウの位置・サイズも引き続き保存します。リボンの表示・非表示と並び順は「設定 → リボン」で変更できます。

アカウント一覧の上端は受信トレイの本文位置に合わせ、他のタブへ移っても動かしません。上部のアカウント数・切替ボタン・重複した監視状態は表示せず、各アカウントの状態は一覧に表示します。操作に失敗した場合の案内は引き続き表示します。

## 使い方

1. AppDock左のリボンの「Gmail」を押すか、「Gmailを開く」を実行します。既定ではAppDock本体のページに表示します。パネル、コマンドパレット、ピン留め、ショートカットからも同じ画面を開けます。
2. 表示されたGoogleの画面でログインします。パスワード入力・二段階認証は利用者自身が行います。
3. 「アカウント設定」を開くと「＋ アカウントを追加」が表示され、独立したログイン領域を追加できます（最大10個）。左側でアカウントを切り替え、設定画面で表示名や順番を変更できます。
4. ログイン済みのアカウントは、起動時に受信トレイ先頭ページを裏側で読み込み、監視を開始します。タブを一度ずつ開く必要はありません。起動後に初めて確認できた未読も、その時点の新着として取り込みます。監視OFFから再開した場合も未読を取り込み直します。

追加直後の表示名は「新しいアカウント」です。ログイン後、Gmailヘッダーから名前を取得できたら自動設定し、名前がなければメールアドレスを使います。仮名のときだけ設定するため、自分で変更した名前や一度自動設定した名前は上書きしません。以前の「アカウント 1」などの仮名も対象です。Gmail側の表示から取得できない間は仮名を保ち、設定画面から手動変更できます。

上部の「新着一覧」で、送信元・件名・検知時刻と「未読・既読・状態未確認」を確認できます。バッジの件数は、検知した新着のうち未読を確認できたスレッドの数です。同じスレッドに複数の新着履歴があっても1件と数え、既読になったら件数とトレイの印を更新します。既読への変更は受信トレイの観測時に反映し、メール本文から戻ったときも更新します。

削除・アーカイブなどで、同じ受信トレイの確認範囲から消えたメールは、件数と新着履歴から外します。最後のメールを削除して受信トレイが空になった場合も更新します。ページ外への移動やカテゴリ変更だけでは削除と断定しません。新着一覧から開こうとしたメールが、読み込み済みの受信トレイに見つからなければ、再読み込みせず受信トレイと案内を表示します。

すべてのアカウント、または選択中のアカウントで絞り込めます。「未読だけ」と送信元・件名・アカウント名の検索を組み合わせられます。「未読だけ」のチェック状態は保存し、タブ移動やAppDock再起動後も引き継ぎます。検索は英字の大文字/小文字、全角/半角の違いを吸収します。表示の絞り込みは新着件数やクリアの範囲を変えません。クリアは選んだアカウント範囲の全新着へ適用します。

「メールを開く →」で該当アカウントを選び、現在の受信トレイにある対象スレッドをGmailの操作として開きます。受信トレイに見つからない場合は受信トレイへ案内します。Gmailの設定によって、開くと既読になります。本文を開いている間はそのアカウントの監視を休止し、受信トレイへ戻ると未読状態を更新します。

新着表示のクリアはバッジとトレイの印を解除しますが、履歴とGmailの未読状態は残します。クリア済みのメールは未読のままでも再計上せず、新しい返信の到着などを検知した場合に再び新着として扱います。既読を未読に戻すだけでは通知を出し直しません。

Gmailウィンドウの位置・サイズと最大化状態は保存し、次回起動時に復元します。モニター構成が変わって画面外へ外れた場合は、表示できる範囲へ戻します。左側のアカウント一覧を選ぶか、「次のアカウント」「前のアカウント」コマンドで順に切り替えられ、最後/先頭からは循環します。GmailのWeb画面にフォーカスがあるときは切替先へ入力を引き継ぎ、クリックし直さず続けてキーを使えます。ほかのウィンドウから切り替えるときは、そのフォーカスを保ち、Gmailを開く・復元する・アクティブにする操作は行いません。画面を開くときは「Gmailを開く」を使ってください。既定キーは`Ctrl+Tab`と`Ctrl+Shift+Tab`で、GmailのWeb画面・新着一覧・アカウント設定で使えます。キーの変更やグローバル化はAppDockのショートカット設定で行います。

戻る・進む・再読み込み・受信トレイへの移動に対応します。Gmailの操作はWeb画面で直接行います。新着一覧・アカウント設定の表示中も、裏側の受信トレイの監視は続きます。Gmailウィンドウの×は画面を隠すだけで、他のアカウントも含めて監視を続けます。Appletを無効化するとWeb画面と監視を停止し、ログイン情報は保持します。完全終了はAppDockの終了操作です。

選択していないアカウントや新着一覧の裏側でも、Gmailの画面更新に必要な描画を維持します。初めて選択する前のアカウントも対象です。背景では約30秒間隔でページのアクティブ状態を更新し、Gmailの同期開始・再開を促します。メールの反映には通信時間もかかります。操作中のGmailは通常のフォーカス動作を使い、画面の自動切替・Windowsのフォーカス移動・定期再読み込みは行いません。Googleの認証画面ではこの処理を解除し、利用者自身のログインを待ちます。背景のページを継続動作させるため、アカウント数に応じてCPU・メモリーを使用します。

アカウント削除は確認後、その枠のログイン情報とサイトデータを消去します。Googleアカウントやメールそのものは削除しません。最後の枠は残し、ログアウトはGmail画面で行ってください。外部リンクは既定では確認後に既定のアプリで開きます。「開く」と「次回から聞かずに開く」を一緒に選ぶと、次回以降の確認を省略します。キャンセルでは設定を変えません。「設定 → 外部リンクを確認せずに開く」でも変更でき、OFFに戻すと再び確認します。対象はHTTP(S)とメール作成リンクです。

受信トレイのツールバーは「戻る」「進む」「リロード」「受信トレイへ」のアイコンを表示します。カーソルを重ねると操作名が表示されます。「新着表示をクリア」は新着一覧、または同名コマンドから実行できます。Windowsの新着通知をクリックすると「Gmailを開く」を実行し、設定された本体ページまたは別ウィンドウを開きます。

## 設定

「設定 → ツールバーを表示」で、受信トレイ・新着一覧・アカウント設定・設定のツールバーエリアを一括で表示/非表示にできます。非表示でも上部タブ、コマンド、切替キーと各画面の内容は利用できます。左上のGmailの下にはApplet自身のバージョンを表示します。

「アカウント設定 → アカウントの順番」の上下ボタンで並べ替えられます。左側の一覧と次/前の切替キーに同じ順番を使い、再起動後も保持します。並べ替えで選択中のアカウントやログイン先は変わりません。表示名はEnterでも保存でき、「元に戻す」で未保存の変更を戻せます。

GmailのヘッダーにあるGoogleアカウントのアバターを一覧と設定画面に表示します。ログイン前、画像がない場合、取得できない場合は表示名の先頭文字で代替します。画像は該当アカウントのログイン済みブラウザー領域から取得し、右上に表示される画像を使います。ホストの画像データは起動中だけ保持し、Googleのプロフィール自体は変更しません。

「このアカウントの新着を監視する」でアカウントごとの監視をON/OFFできます。初期値はONで、既存のアカウントもONを引き継ぎます。OFFにするとそのアカウントの新着件数・履歴を消去し、通知と通知音を止めます。ログインと音の設定は保持し、Gmailの操作や背景のページ更新は続けます。ONへ戻すと、受信トレイで確認できる未読を新着として取り込み直します。AppDockの「設定 → Gmail」の全体監視がOFFなら、アカウント別の設定がONでも監視しません。

Gmailの操作画面・新着一覧・アカウント設定の色は、AppDockのテーマ（ライト・ダーク・システム）に連動し、変更をその場で反映します。GmailのWebページ内の色はGoogle側のテーマ設定に従います。

Gmail画面の「アカウント設定」の隣にある「設定」タブで「新着の監視」「新着通知」「通知に送信元と件名を表示」を変更できます。変更は即時保存し、AppDockの「設定 → Gmail」と同じ設定に反映します。どちらの画面から変更しても同期し、再起動後も保持します。全体の監視をOFFにすると全アカウントの新着履歴・件数を消去し、通知と音を止めます。ONへ戻すと、監視中のアカウントの未読を取り込み直します。

通知は未読の新着だけを対象とし、起動時に取り込んだ未読も含みます。初期設定では件数だけを通知し、送信元・件名の通知は明示的に有効にした場合に表示します。通知にはAppDock本体の通知設定も適用します。トレイのメニューへの追加・クリック動作・グローバルショートカットはホストで設定します。

「新着履歴の保存件数」も設定タブで変更できます。アカウントごとに10・20・30・40・50件から選び、初期値は50件です。件数を減らすと古い履歴を消去し、増やしても消去済みの履歴は戻りません。履歴の件数を減らしても、未読の新着件数の集計は変わりません。保存件数の設定は再起動後も保持しますが、履歴自体は起動中だけ保持します。

| コマンドID | 操作 |
| --- | --- |
| `at365.gmail.open` | Gmailを開く（停止中も明示実行で有効化） |
| `at365.gmail.back` | 選択アカウントのWeb画面を戻る |
| `at365.gmail.forward` | 選択アカウントのWeb画面を進む |
| `at365.gmail.reload` | 選択アカウントのWeb画面をリロード |
| `at365.gmail.inbox` | 選択アカウントの受信トレイへ移動 |
| `at365.gmail.acknowledge` | 全アカウントの新着表示をクリア |
| `at365.gmail.nextAccount` | 次のアカウント（既定: Ctrl+Tab） |
| `at365.gmail.previousAccount` | 前のアカウント（既定: Ctrl+Shift+Tab） |

通知音は「アカウント設定 → このアカウントの通知音」で個別にON/OFFできます。初期状態はOFFです。登録済みの一覧から選び、「WAVを登録」で16MB以下の音声を追加します。元のファイル名で保存し、同名別内容は登録を拒否します。同名同内容は既存音声を使います。一覧はファイル同期で届いた素材も自動更新します。ファイル未指定では標準のビープ音を使い、標準音へ戻す操作と、OFFのままでの試聴も利用できます。

新着音はWindowsやAppDockのデスクトップ通知設定と独立し、両方の通知がOFFでも、そのアカウントの音がONなら再生します。Windows通知自身の音は抑制し、二重に鳴らしません。監視OFFでは検知も音も止まります。OSの音量・ミュート設定は適用されます。起動時の未読にも音設定を適用し、同じ更新の複数新着は1回の音で知らせます。登録時にコピーするので元ファイルは移動・削除できます。PC専用設定に保存済みの外部ファイル参照も起動時に登録し、元ファイルがない場合は選び直しを案内します。枠を削除しても登録素材は残ります。

## 保存先・現在の制約

- 一般設定: AppDockのEXE隣の`settings.json`。
- アカウント枠・順番・選択・枠ごとの監視/通知音割り当て: このPCの`%LOCALAPPDATA%/at365/AppDock/profiles/<配置ID>/web-accounts/at365.gmail/accounts.json`。枠自体もPC間で同期しません。
- 登録音声: EXE隣の`data/assets/applets/at365.gmail/sounds/<ファイル名>`。AppDockフォルダーと一緒に同期できます。音声の割り当てはPCごとです。
- ログイン状態: 同じPC専用root内の`web-accounts/at365.gmail/sessions/<account-id>/`。各PCでログインしてください。旧.appdockからの自動移行は行いません。
- 画面の位置・サイズはPC専用root内の`web-accounts/at365.gmail/window-state.json`へ保存します。ログイン情報を含むPC専用rootは公開・他者への共有を避け、継続利用には保持してください。
- Gmail API・OAuthクライアントJSONは使用しません。旧GmailCheckerのAPI用設定・トークンは自動移行しません。旧Webテストのログイン引き継ぎは開発用の明示操作だけです。
- 新着履歴は起動中だけ、各アカウントの最大50件・約48KBまで保持します。終了・Applet停止・監視OFFで消去し、ファイルには保存しません。件数は確認できた未読の新着スレッド数で、メールボックス全体の未読総数や、スレッド内の個々の未読メッセージ数ではありません。履歴の50件上限とは別に集計します。件名・送信元を読み取れない場合も新着検知は継続します。
- 状態を判定できない行や、先頭ページの範囲外へ押し出された行は「状態未確認」とし、未読件数に含めません。削除による消失と判定できない場合は履歴を保持します。別フォルダーや本文の表示中は最後に確認した件数を維持し、受信トレイへ戻ると更新します。Gmailの未読/既読を自動変更する機能はありません。
- 本文や受信トレイのプレビュー文は取得しません。正確な全メール件数、先頭ページにないメールへの直接移動、LLM/TTSは今後の機能です。
- 先頭ページの新しいメール行と、既存未読スレッドの最終メッセージIDの変化を検知します。起動・監視再開後の初回は未読を取り込みます。同じ起動中の再ログイン・再読み込み・別フォルダーからの復帰は基準を作り直し、既存メールを重複通知しません。
- 別フォルダーや受信トレイの2ページ目以降、設定・メール本文を開いている間はその枠の監視を休止します。他の枠の受信トレイは監視を続けます。休止中・終了中の新着を後からすべて回収する方式ではありません。
- GmailのDOM変更、独自の受信トレイ設定・カテゴリ、IDを読み取れない画面では検知できない場合があります。空の受信トレイは明示的な空状態を認識できる場合だけ基準を作ります。アーカイブ解除や一部の自己返信など、Web画面の情報だけでは新着との区別が難しい操作があります。
- Googleがログインを拒否した場合、認証画面の表示を確認してください。認証手順やUser-Agentを偽装する機能はありません。
- Googleの認証処理で`accounts.youtube.com`を経由する場合があります。0.1.1以降はこの認証先に対応しています。更新後はAppDockを完全終了して起動し直し、Gmail画面で再読み込みまたは「受信トレイ」を押してください。
- ログアウト後にGoogleのGmail案内ページ`workspace.google.com`へ移動する場合があります。0.1.2以降はこの移動先にも対応しています。案内ページのログイン、または「受信トレイ」から再ログインできます。
- Google認証が日本向けの`accounts.google.co.jp`を経由する場合にも、0.1.3以降は対応しています。

## AppDockからの更新

AppDockの「設定 → バージョン情報・更新」の一括更新、またはこのAppletの個別更新ボタンを利用できます。配布元が`update.json`と`update.zip`を提供している場合に対応します。更新元は「インストール済みのApplet」の「更新元の設定」で変更し、保存してください。ローカルフォルダー・UNC・HTTP(S)・GitHub Releaseに対応し、「既定に戻す」も利用できます。

更新内容を確認して再起動すると配布ファイル一式を交換します。AppDock側の設定・有効状態・保存データは保持します。詳細は[AppDockの更新操作](../AppDock.at365/README.md#アップデート)を参照してください。
