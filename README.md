# Applet.Gmail.at365

AppDockから、複数アカウントのGmail Web画面を開くAppletです。Googleの画面で利用者自身がログインし、アカウントごとにログイン状態を保存します。受信トレイの画面更新から新着を検知し、送信元・件名・検知時刻を新着一覧に表示します。アカウント一覧・AppDockのパネル・トレイの印とデスクトップ通知でも知らせます。

## 動作環境と導入

Windows x64、**AppDock 0.13.1以降**、Googleに接続できるインターネット環境が必要です。WebContentsViewはAppDock内蔵のElectronを使うため、別のブラウザーRuntimeやNode.jsのインストールは不要です。Gmail 0.2.2への更新時は、先にAppDock本体も更新してください。

AppDockを完全終了し、配布された`Applet.Gmail.at365`フォルダー全体をEXE隣の`extensions`へ置きます。`extension.json`、`index.js`、`monitor.js`、`web/`が必要です。更新時もフォルダー全体を置き換え、`.appdock`と`settings.json`は保持してください。起動後、Applet一覧で「Gmail」を有効にします。

## 使い方

1. 「Gmailを開く」を実行します。パネル、コマンドパレット、ピン留め、ショートカットから開けます。
2. 表示されたGoogleの画面でログインします。パスワード入力・二段階認証は利用者自身が行います。
3. 「＋ アカウントを追加」で独立したログイン領域を追加できます（最大10個）。左側でアカウントを切り替え、「アカウント設定」で表示名を変更できます。
4. Gmailの受信トレイ先頭ページを表示すると、そのアカウントの監視を開始します。起動後に初めて確認できた未読も、その時点の新着として取り込みます。監視OFFから再開した場合も未読を取り込み直します。

上部の「新着一覧」で、送信元・件名・検知時刻と「未読・既読・状態未確認」を確認できます。バッジの件数は、検知した新着のうち未読を確認できたスレッドの数です。同じスレッドに複数の新着履歴があっても1件と数え、既読になったら件数とトレイの印を更新します。既読への変更は受信トレイの観測時に反映し、メール本文から戻ったときも更新します。

すべてのアカウント、または選択中のアカウントで絞り込めます。「受信トレイへ →」で該当アカウントの受信トレイを開きます。新着表示のクリアはバッジとトレイの印を解除しますが、履歴とGmailの未読状態は残します。クリア済みのメールは未読のままでも再計上せず、新しい返信の到着などを検知した場合に再び新着として扱います。既読を未読に戻すだけでは通知を出し直しません。

戻る・進む・再読み込み・受信トレイへの移動に対応します。Gmailの操作はWeb画面で直接行います。新着一覧・アカウント設定の表示中も、裏側の受信トレイの監視は続きます。Gmailウィンドウの×は画面を隠すだけで、他のアカウントも含めて監視を続けます。Appletを無効化するとWeb画面と監視を停止し、ログイン情報は保持します。完全終了はAppDockの終了操作です。

0.2.2では、選択していないアカウントや新着一覧の裏側でも、Gmailの画面更新に必要な描画を維持します。初めて選択する前のアカウントも対象です。背景のページを継続動作させるため、アカウント数に応じてCPU・メモリーを使用します。

アカウント削除は確認後、その枠のログイン情報とサイトデータを消去します。Googleアカウントやメールそのものは削除しません。最後の枠は残し、ログアウトはGmail画面で行ってください。外部リンクは確認後に既定のアプリで開きます。

## 設定

AppDockの「設定 → Gmail」で「新着の監視」「新着通知」「通知に送信元と件名を表示」を変更できます。通知は未読の新着だけを対象とし、起動時に取り込んだ未読も含みます。初期設定では件数だけを通知し、送信元・件名の通知は明示的に有効にした場合に表示します。通知にはAppDock本体の通知設定も適用します。トレイのメニューへの追加・クリック動作・グローバルショートカットはホストで設定します。

| コマンドID | 操作 |
| --- | --- |
| `at365.gmail.open` | Gmailを開く（停止中も明示実行で有効化） |
| `at365.gmail.acknowledge` | 全アカウントの新着表示をクリア |

## 保存先・現在の制約

- 一般設定: AppDockのEXE隣の`settings.json`。
- アカウント一覧: `.appdock/web-accounts/at365.gmail/accounts.json`。
- Cookie・サイトデータなどのログイン状態: `.appdock/web-accounts/at365.gmail/sessions/<account-id>/`。ログイン情報を含むので、公開・他者への共有を避けてください。継続利用にはこのフォルダーを保持します。
- Gmail API・OAuthクライアントJSONは使用しません。旧GmailCheckerのAPI用設定・トークンは自動移行しません。旧Webテストのログイン引き継ぎは開発用の明示操作だけです。
- 新着履歴は起動中だけ、各アカウントの最大50件・約48KBまで保持します。終了・Applet停止・監視OFFで消去し、ファイルには保存しません。件数は確認できた未読の新着スレッド数で、メールボックス全体の未読総数や、スレッド内の個々の未読メッセージ数ではありません。履歴の50件上限とは別に集計します。件名・送信元を読み取れない場合も新着検知は継続します。
- 状態を判定できない行や、先頭ページから見えなくなった行は「状態未確認」とし、未読件数に含めません。別フォルダーや本文の表示中は最後に確認した件数を維持し、受信トレイへ戻ると更新します。Gmailの未読/既読を自動変更する機能はありません。
- 本文や受信トレイのプレビュー文は取得しません。正確な全メール件数、個別メールへの直接移動、アカウント別通知音、LLM/TTSは今後の機能です。
- 先頭ページの新しいメール行と、既存未読スレッドの最終メッセージIDの変化を検知します。起動・監視再開後の初回は未読を取り込みます。同じ起動中の再ログイン・再読み込み・別フォルダーからの復帰は基準を作り直し、既存メールを重複通知しません。
- 別フォルダーや受信トレイの2ページ目以降、設定・メール本文を開いている間はその枠の監視を休止します。他の枠の受信トレイは監視を続けます。休止中・終了中の新着を後からすべて回収する方式ではありません。
- GmailのDOM変更、独自の受信トレイ設定・カテゴリ、IDを読み取れない画面では検知できない場合があります。空の受信トレイは明示的な空状態を認識できる場合だけ基準を作ります。アーカイブ解除や一部の自己返信など、Web画面の情報だけでは新着との区別が難しい操作があります。
- Googleがログインを拒否した場合、認証画面の表示を確認してください。認証手順やUser-Agentを偽装する機能はありません。
- Googleの認証処理で`accounts.youtube.com`を経由する場合があります。0.1.1以降はこの認証先に対応しています。更新後はAppDockを完全終了して起動し直し、Gmail画面で再読み込みまたは「受信トレイ」を押してください。
- ログアウト後にGoogleのGmail案内ページ`workspace.google.com`へ移動する場合があります。0.1.2以降はこの移動先にも対応しています。案内ページのログイン、または「受信トレイ」から再ログインできます。
- Google認証が日本向けの`accounts.google.co.jp`を経由する場合にも、0.1.3以降は対応しています。
